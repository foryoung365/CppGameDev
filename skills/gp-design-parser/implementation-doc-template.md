# 功能实现文档模板

输出最终结果时，优先使用以下结构。可根据策划案复杂度合并小节，但不要缺少“版本识别结果”“本次变更摘要”和“待确认项”。

## 1. 版本识别结果

- 原始文档：文档名称或用户提供的标识
- 当前版本：识别出的最新版本号、日期或生效标识
- 版本变更记录摘要：版本记录区对当前版本的原始描述
- 当前版本色标：颜色名称、视觉表现形式、适用位置
- 识别说明：若存在歧义、低清截图、多个候选颜色，在此说明

## 2. 本次变更摘要

按条列出本次版本新增、修改、删除的核心点。每条至少包含：

- 变更类型：新增 / 修改 / 删除 / 待确认
- 变更对象：系统、玩法模块、界面元素、配置项、触发条件等
- 变更摘要：一句话说明本次改了什么
- 来源位置：章节、页码、表格名、流程图节点或截图区域

## 3. 功能目标与适用范围

- 功能目标：该功能需要解决什么问题
- 适用对象：玩家、角色、队伍、公会、活动阶段、服务器等
- 生效范围：常驻、活动期、特定地图、特定玩法模式等

## 4. 名词与对象定义

列出实现需要依赖的核心对象、枚举、状态和值域。若沿用旧规则，注明 `来源：背景沿用`。

## 5. 核心规则

按主题拆分规则，建议每条规则使用以下格式：

- 规则名称：
- 规则描述：
- 触发条件：
- 执行结果：
- 限制条件：
- 来源：本次变更 / 背景沿用 / 推断
- 备注：如有旧版差异、替换关系、删除线索，在此补充

## 6. 流程与状态变化

- 进入条件
- 状态流转
- 退出条件
- 失败回退
- 与其他系统的联动节点

必要时用编号流程描述，不必强制使用图。

## 7. 数据、配置与持久化

- 配置表或配置项
- 默认值与取值范围
- 是否需要热更
- 持久化字段
- 重置时机
- 跨天、跨周、活动切期处理

## 8. 客户端与服务端职责

- 服务端：判定、结算、状态维护、消息下发、持久化
- 客户端：展示、交互、红点、引导、表现

若存在共享逻辑、GM 指令、后台配置或日志埋点，也在此补充。

## 9. 接口、事件与通知

- 请求接口
- 响应字段
- 推送事件
- 条件校验失败的错误码或提示
- 与其他系统交互的输入输出

## 10. 边界与异常处理

- 条件不满足时如何处理
- 配置缺失或非法时如何处理
- 并发、重复触发、跨服或断线重连影响
- 旧数据兼容与版本切换影响

## 11. 验证关注点

- 正常路径
- 边界值
- 状态切换
- 回滚与重登
- 与旧规则兼容

## 12. 待确认项

- 问题点
- 影响范围
- 当前暂定处理
- 需要策划确认的内容

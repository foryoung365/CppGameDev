# Gameplay 经验循环集成实施计划

> 历史说明：本文为经验库与经验检索能力接入阶段的内部实施计划中文整理版。

## 目标

在不改变既有 gameplay 受理主路径的前提下，为 C++ MMORPG gameplay 插件补充一套 CE 风格的经验积累与经验检索循环，并明确“历史经验始终只是次级上下文”。

## 架构摘要

- 保持运行时主路径 `request -> gameplay-context-guard -> task-intake-router -> pre-plan` 不变
- 在主路径之外叠加第二优先级的经验系统
- 新增一个检索代理、一个共享经验检查技能、一个经验写入技能与一个经验刷新技能
- 经验文档存放于宿主项目，而不存放于插件仓库
- 默认经验路径位于宿主项目命名空间文档目录；如宿主项目 `claude.md` 有显式覆盖，则以覆盖为准

## 技术栈

- Claude Code 插件 Markdown 资产
- 宿主项目 Markdown 经验文档
- PowerShell 结构校验脚本
- 既有 gameplay 与 SVN 工作流规则

## 执行注意事项

- 证据优先验证仍是首要事实来源，历史经验只是次级上下文
- 插件仓库中不附带任何示例经验文档
- 不在安装时预创建宿主项目经验目录；目录仅在 `gp-compound` 首次实际写入时惰性创建
- SVN 交付仍以完整功能为粒度，不允许因为经验循环而引入按步骤提交行为

## 运行时契约

- 宿主项目经验库默认根目录：
  - `docs/cmg/solutions/bugs/`
  - `docs/cmg/solutions/patterns/`
- 可选覆盖：
  - 若当前宿主项目 `claude.md` 显式定义经验库根目录，则优先使用该位置
- 检索触发点：
  - `intake`
  - `gp-debug`
  - `gp-review`
  - `svn-handoff`
- 写入触发点：
  - 显式 `/cmg:gp-compound`
  - 显式 `/cmg:gp-compound-refresh`
  - `gp-review` 与 `svn-handoff` 中的工作流提示
- 硬性写入门槛：
  - 若证据、结论、验证任一项不明确且非当前，就不得创建或更新经验文档

## 关键任务

### 任务 1：定义经验库契约与写作资产

- 编写 `gp-compound`
- 编写 `gp-compound-refresh`
- 提供 bug 轨道模板、knowledge 轨道模板与经验 schema
- 明确允许动作、硬性门槛、重叠处理与范围过滤

### 任务 2：实现经验检索与共享检查逻辑

- 编写 `gp-experience-researcher`
- 编写 `gp-experience-researcher`
- 建立宿主项目形态的经验夹具
- 明确“只返回摘要，不倾倒整篇文档”

### 任务 3：将经验检索接入既有运行时流程

- 在 `intake` 后补充经验检查
- 在 `gp-debug` 中把既有经验作为候选线索，而非证据
- 在 `gp-review` 中核对当前变更与既有经验的一致或冲突关系
- 在 `gp-svn-handoff` 中判断当前成果是否值得沉淀为新经验

### 任务 4：校验经验层不越权

- 明确当前代码、当前证据与当前验证始终高于历史经验
- 明确经验层不得替代编译门禁与定向验证
- 明确经验文档只写入宿主项目

## 预期结果

完成后，插件应具备以下能力：

- 在关键 workflow 节点检索宿主项目既有经验
- 在满足硬性门槛时，将稳定经验写回宿主项目经验库
- 在经验过期、重复或失真时执行刷新维护
- 严格保持“经验只是次级上下文，不得越权”
